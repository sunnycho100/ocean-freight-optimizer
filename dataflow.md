# Ocean Freight Optimizer — Data Flow & File Reference

This document maps the full data pipeline, every file the system produces/consumes, and the exact column schemas required. Use it to generate mock data when real scraped data is unavailable.

## File-by-File Reference

### 1. `destinations.txt` (Manual Input)

Plain-text list of inland destination cities, one per line.

```
VALENCE, DROME, FRANCE
MUENSTER, NW, GERMANY
TEVEROLA, ITALY
OEGSTGEEST, NETHERLANDS
KOBIERZYCE, POLAND
KOMAROM, HUNGARY
BAUMGARTENBERG, AUSTRIA
TAMPERE, FINLAND
```

### 2. `destination_configs.json` (Generated by url_checker)

Maps each destination to its ONE Line location code and available ports.

```json
{
  "VALENCE, DROME, FRANCE": {
    "locationCode": "FRVAF",
    "pols": "",
    "pods": "BEANR,FRFOS,FRLEH,NLRTM"
  },
  "OEGSTGEEST, NETHERLANDS": {
    "locationCode": "NLGSG",
    "hapagLocationCode": "NLOGE",
    "pols": "",
    "pods": "BEANR,NLRTM"
  }
}
```

| Field | Type | Description |
|-------|------|-------------|
| `locationCode` | string | ONE Line UN/LOCODE (e.g. `FRVAF`) |
| `hapagLocationCode` | string (optional) | Alternate code for Hapag if different |
| `pols` | string | Comma-separated ports of loading (often empty — defaults used) |
| `pods` | string | Comma-separated ports of discharge (UN/LOCODEs) |

### 3. `source/ocean_freight.xlsx` (Manual Input)

Ocean freight rates from origin (Busan) to various PODs. **You must create this manually.**

| Column | Type | Example |
|--------|------|---------|
| `POD` | string | `ROTTERDAM` / `ANTWERP` / `LE HAVRE` etc. |
| `Currency` | string | `EUR` |
| `20 FT` | numeric | `1509` |
| `40 FT` | numeric | `2380` |

POD names must match exactly the POD values in the scraped inland rate data.

### 4. `downloads/ONE_Inland_Rate_YYYYMMDD.xlsx` (Scraped Output)

**Produced by**: `quick_download_refactored.py`
**Sheet name**: `Inland Rates`
**Source**: ONE Line inland tariff website

#### Columns (scraped from web table + metadata added by processor)

| # | Column | Type | Source | Notes |
|---|--------|------|--------|-------|
| A | `Destination` | string | Added by script | Destination city from destinations.txt |
| B | varies (e.g. `Origin / POL`) | string | Web table | Port of loading |
| C | `Container Type & Size` | string | Web table | e.g. `20 FT Dry`, `40 FT Dry`, `40 FT High Cube Dry` |
| D | `POD` | string | Web table | Port of discharge |
| E | `Weight Range` | string | Web table | e.g. `0 ~ 21000 KGS` |
| F | `Currency` | string | Web table | e.g. `EUR`, `USD` |
| G | `Rate` | numeric | Web table | Inland transport rate |
| H | `Remarks` | string | Web table | e.g. `Truck; Valid until 2025-12-31` |
| I | (additional table cols) | mixed | Web table | Other scraped columns |
| J | *(spacer)* | empty | Metadata | — |
| K | *(spacer)* | empty | Metadata | — |
| L | `City Name` | string | Metadata | Only on first row per destination |
| M | `Total Count` | int | Metadata | Expected row count from web page |
| N | `Validation` | string | Metadata | `TRUE` or `FALSE (Expected: X, Got: Y)` |

**Container Type values** (ONE Line):
- `20 FT Dry`
- `40 FT Dry`
- `40 FT High Cube Dry`
- `20 FT Reefer`
- `40 FT Reefer High Cube`

**Transport Mode** (extracted from Remarks — text before first semicolon):
- `Truck`
- `Rail`
- `Barge`
- `Barge/Truck`
- `Rail/Truck`

### 5. `downloads/ONE_Inland_Rate_Processed_YYYYMMDD_HHMMSS.xlsx` (Post-Processed)

**Produced by**: `ONE_processor.py`
**Consumes**: `ONE_Inland_Rate_YYYYMMDD.xlsx` + `source/ocean_freight.xlsx`

Drops the metadata/validation columns (J–N), enriches with ocean rates and rankings.

| Column | Type | Source | Notes |
|--------|------|--------|-------|
| `Destination` | string | Raw file | e.g. `VALENCE, DROME, FRANCE` |
| `Container Type & Size` | string | Raw file | e.g. `40 FT High Cube Dry` |
| `POD` | string | Raw file | e.g. `ROTTERDAM` |
| `Rate` | numeric | Raw file | Inland rate |
| `Currency` | string | Raw file | Currency code |
| `Remarks` | string | Raw file | Full remarks text |
| *(other scraped cols)* | mixed | Raw file | First 9 columns kept |
| `Transport Mode` | string | Derived | Extracted from Remarks (text before `;`) |
| `Ocean Rate` | numeric | Lookup | Matched from ocean_freight.xlsx by POD + container size |
| `Total Rate` | numeric | Calculated | `Rate + Ocean Rate` |
| `Cost Rank` | int | Calculated | 1 = cheapest. Grouped by (Destination + Container Type) |
| `Total Routes` | int | Calculated | Count of routes per (Destination + Container Type) |

### 6. `downloads/hapag_surcharges.xlsx` (Scraped Output)

**Produced by**: `hapag_checker.py`
**Sheet name**: `Import Surcharges`
**Source**: Hapag-Lloyd quote website

The file has **4 skipped header rows** at the top (read with `skiprows=4`).

| Column | Type | Example |
|--------|------|---------|
| `From` | string | `BUSAN` |
| `To` | string | `VALENCE, DROME` |
| `Via` | string | `FOS SUR MER` (or empty) |
| `Description` | string | `Ocean Freight Basic`, `Terminal Handling Charge Dest.`, `Destination Landfreight` |
| `Curr.` | string | `USD`, `EUR` (empty for category headers like Destination Landfreight) |
| `20STD` | numeric/string | `1200` or `-` |
| `40STD` | numeric/string | `1800` or `-` |
| `40HC` | numeric/string | `1900` or `-` |
| `Transport Remarks` | string | e.g. `Inland transport included` |

**Row types** (determined by `Description` field):
- **Ocean Freight** — main ocean freight charge
- **Destination Landfreight** — inland delivery charge (may have sub-options below)
  - Sub-option rows have a non-empty `Curr.` and descriptions like `Combined...`, `Between...`, `From...`
- **Other charges** — e.g. `Terminal Handling Charge Dest.`, `ISPS Surcharge`, `Low Sulphur Surcharge`, etc.

### 7. `.env` (Manual Input — Hapag only)

```
HAPAG_EMAIL=your_email@example.com
HAPAG_PASSWORD=your_password_here
```

## Frontend TypeScript Types

```typescript
// ONE Line types
interface Route {
  rank: number;        // 1-based cost ranking
  pod: string;         // Port of discharge
  mode: string;        // Transport mode (Truck, Rail, Barge, etc.)
  remarks?: string;    // Full remarks text
  totalRate: number;   // Ocean + Inland rate
  oceanRate?: number;  // Ocean freight component
  inlandRate?: number; // Inland transport component
}

interface LaneData {
  destination: string;
  containerType: string;  // "20 FT Dry" | "40 FT Dry" | "40 FT High Cube Dry"
  currency: string;       // "EUR" | "USD"
  routes: Route[];
}

// HAPAG types
interface HapagChargeItem {
  description: string;
  curr: string;
  value20STD: string;
  value40STD: string;
  value40HC: string;
  subOptions?: HapagSubOption[];
}

interface HapagSubOption {
  description: string;
  value20: string;
  value40: string;
  value40HC: string;
}

interface HapagRoute {
  from: string;
  to: string;
  via: string;
  oceanFreight?: HapagChargeItem;
  destinationLandfreight?: HapagChargeItem;
  otherCharges: HapagChargeItem[];
  availableContainers: { '20STD': boolean; '40STD': boolean; '40HC': boolean };
}

interface HapagLaneData {
  destination: string;
  route: HapagRoute;
}
```

## Summary: Files Needed for Mock Data

To run the system without real scraped data, you need to create these files:

| # | File | Format | Purpose |
|---|------|--------|---------|
| 1 | `source/ocean_freight.xlsx` | Excel | Ocean rates: POD, Currency, 20 FT, 40 FT |
| 2 | `downloads/ONE_Inland_Rate_Processed_YYYYMMDD_HHMMSS.xlsx` | Excel | Final processed ONE data (or create #3 + #1 and run `ONE_processor.py`) |
| 3 | `downloads/ONE_Inland_Rate_YYYYMMDD.xlsx` | Excel | Raw inland rates (alternative: create this + #1 → run processor) |
| 4 | `downloads/hapag_surcharges.xlsx` | Excel | HAPAG surcharge data with 4 blank header rows then 9 columns |
| 5 | `destinations.txt` | Text | Destination list (already exists) |
| 6 | `destination_configs.json` | JSON | Location configs (already exists) |

### Minimum viable mock setup (API server only)

You only need **two files** to get the API + frontend working:

1. **`downloads/ONE_Inland_Rate_Processed_YYYYMMDD_HHMMSS.xlsx`** — with columns:
   `Destination`, `Container Type & Size`, `POD`, `Rate`, `Currency`, `Remarks`, `Transport Mode`, `Ocean Rate`, `Total Rate`, `Cost Rank`, `Total Routes`

2. **`downloads/hapag_surcharges.xlsx`** — with 4 blank rows at top, then data rows with columns:
   `From`, `To`, `Via`, `Description`, `Curr.`, `20STD`, `40STD`, `40HC`, `Transport Remarks`

### Container type mapping (ONE ↔ HAPAG)

| ONE Line | HAPAG | Code |
|----------|-------|------|
| `20 FT Dry` | `20STD` | D2 |
| `40 FT Dry` | `40STD` | D4 |
| `40 FT High Cube Dry` | `40HC` | D5 |

### Currency conversion used in Summary view

The frontend Summary Dashboard uses a hardcoded `USD_TO_EUR = 0.86` conversion rate when comparing ONE (EUR) vs HAPAG (USD) prices.
